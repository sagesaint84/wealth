# Wealth 홈·메뉴 개편 검토 및 검증

## 참고와 작업 범위

[사용자가 공유한 상담](https://chatgpt.com/share/6a9eeb43-c6c8-83ee-ba46-b0eea1fa0d86), 첨부 상담 텍스트와 이전 앱 녹화를 참고했다. 공유 상담의 핵심인 기존 계좌 관계의 의미 보존, v2/legacy 안전성, v3 순포지션 원복을 현재 변경사항과 대조했다. 문서 안의 과거 작업 지시는 새 실행 권한으로 간주하지 않았다.

작업 시작 브랜치는 `codex-refactor`였으며 working tree는 clean이 아니었다. v1.0.5 관련 기존 미커밋 변경을 보존하고 검토했다. 현재 사용자가 화면 구현과 단계별 커밋을 요청함에 따라 거래 처리 보완과 UI 변경을 나누어 기록했다. main, 운영환경, 실제 사용자 데이터 및 dependency는 변경하지 않았다.

## 화면 결정

| 메뉴 | 구성 |

| 홈 | 순자산 → 현금·예적금/등록 부채 → 자산 구성/바로가기 → 시장지수 |
| 투자 | 기존 포트폴리오 → 히트맵 → 보유종목 → 주식기록 |

| 가계부 | 기존 월별 내역, 카드, 고정지출, 입력창 |
| 설정 | 가족·OpenAPI·계좌 연결·비밀번호·로그아웃·테마·백업/복원 |

PC 왼쪽 메뉴 / 모바일 하단 5개 메뉴와 상단 설정 버튼. 가족 필터는 기존 전역 동작을 유지하면서 공통 상단으로 모았다. 전체 삭제는 설정 내 접힌 주의 영역에 배치했다. 브라우저 뒤로/앞으로, 현재 메뉴 표시와 키보드 포커스를 지원한다.

홈 금액은 `renderSummary`의 기존 계산 결과를 이벤트로 전달해 표시한다. owner 규칙, 환율 계산, 자산 분류, 순자산 정책을 새로 만들지 않았다. 기존 등록 부채 기준으로, 미정산 카드 청구금액을 새로 부채에 합산하지 않는다. 신규 순자산 history/전략 버킷/카드 청구기간은 구현하지 않았다.

## 기존 변경 검토에서 보완한 문제

1. **CONFIRMED BUG — v2 수정의 암묵적 v3 전환**: 새 자동 상계 관계가 생긴 후 v2 거래 수정이 overdraft 경로로 들어갔다. 수정 시 기존 version을 기준으로 v2 정책을 유지한다.
2. **CONFIRMED BUG — 고정지출 정의 선저장**: 등록/수정 시 정의를 먼저 저장하고 당월 출금을 시도하여 한도 초과 실패 후에도 정의가 남았다. 미저장 상태에서 검증·출금 계산 후 함께 저장하고 API에서 409로 반환한다.
3. **CONFIRMED BUG — 동일 pair 수정의 중간 한도 검사**: 과거 입금 이후 자금이 사용되면 입금 원복 중간 단계가 한도를 넘어, 유효한 최종 수정까지 거절됐다. 같은 pair 수정은 `새 delta - 기존 delta`를 한 번 적용하고 최종 잔액을 검증한다. v3 net_delta는 수정된 거래 전체 delta이며 component audit는 실제 수정 시 변화량이다.
4. **방어 보강**: 비유한 잔액/한도 및 v3 net_delta를 거절하고, v3 관계 metadata가 손상된 경우 참조 제거 검사를 보수적으로 차단한다.

## 수행한 검증

- `.venv/Scripts/python -m unittest discover -s tests -p 'test_*.py'`: 66개 통과, failure/error/expected failure/unexpected success 없음.
- `node --check`로 기존 `wealth.js`와 신규 `wealth-layout.js` 구문 검사 통과.
- 추가 UI contract 3개: 기존 패널·액션 ID 유지/중복 없음, script 초기화 순서, presentation 계층의 API·저장 로직 부재.
- 가상 데이터 서버에서 데스크톱 기본 크기, 모바일 약 390px, 태블릿 1024px 및 퍼플/화이트 테마를 확인했다.
- 홈 금액 표시, 가족 선택 후 0원 표시, 주요 메뉴 이동, 투자 패널 표시, 손익·배당 패널 표시, 가계부 등록 모달, 설정 버튼 유지 및 주요 화면의 document 가로 overflow 부재를 확인했다.
- 실제 금융 API 및 운영 앱 서버는 실행하지 않았다. `tests/ui_preview.py`는 가상 응답만 반환하고 mutation을 403으로 차단한다.
- preview가 Service Worker를 제공하지 않아 PWA 등록 404가 발생한다. 이는 운영 코드 변경 오류가 아니라 fixture 격리 경계이다. 실제 PWA 설치 및 외부 금융 연결은 이번 UI 검사 대상이 아니다.

## 남은 위험 및 별도 backlog

- **POTENTIAL BUG / 높은 우선순위**: portfolio/ledger 두 JSON 파일의 전체 read-modify-write를 묶는 트랜잭션이나 공통 잠금은 없다. 동시 쓰기, 프로세스 종료, 복원 자체 실패까지 안전성을 보장하지 않는다. 현재 rollback은 ledger 저장 예외 시 portfolio 복원을 시도하는 수준이다.
- **DESIGN AMBIGUITY**: `owner="모두"`는 전체 조회와 실제 소유자 값 의미가 혼용된다. 현재 화면은 기존 정책을 그대로 반영한다.
- **POTENTIAL BUG**: `/api/accounts` USD cash summary, 공동명의 지분 합계 검증은 기존 backlog로 유지한다.
- **기존 정책 한계**: 일반 계좌의 0원 하한과 marker 없는 거래의 보수적 수정/삭제 차단은 유지된다. 과거 잘못된 잔액을 추정해 복원하지 않는다.
- **검증 한계**: 브라우저 확인은 가상 데이터 smoke test이며 모든 운영 데이터 크기, 모든 모달 입력/저장, admin/강제 비밀번호 초기화, 실제 모바일 기기/PWA 설치를 포괄하는 E2E 검증은 아니다.

실제 `.env`와 `data/`는 내용 열람 대신 경로·크기·SHA-256 manifest로 작업 전후 비교했다. 40개 파일의 추가·삭제·크기·hash 변경은 0이었다. 상세 개인 경로와 내용은 보고서에 기록하지 않는다.
