## 5. 동일 날짜

동일 owner/date의 수동 추가는 서버에서 409로 거절하며 replace=true도 무시한다. 화면에서는 중복 안내와 ‘기존 기록 수정’을 제공한다. 날짜 수정 시 다른 기록과 충돌해도 거절한다. 오늘 기록의 기존 당일 교체 확인 정책은 유지한다.

## 6–7. 그래프 / owner

응답 state로 즉시 SVG를 다시 그리며 날짜순 정렬한다. 과거 추가·날짜 수정 후 전체 기간을 표시하고 해당 날짜를 선택한다. 삭제 후 남은 최근 기록을 선택하거나 빈 상태로 돌아간다. 동일 owner 문자열만 표시하며 ‘모두’의 기존 의미를 재설계하지 않았다. 순자산만 있는 수동 기록의 총자산/부채는 0이 아니라 ‘미입력’이다.

## 8–10. 시각적 변경

오늘 기록 primary / 과거 추가와 수정 secondary / 삭제 danger. 기존 공통 button 클래스에 border/radius/weight/gap과 hover/active/disabled/focus-visible을 적용한다. 기존 compact 버튼 크기 예외는 유지한다. 정보 카드에는 hover 이동을 추가하지 않고 panel/line 변수 기반 배경·경계·약한 shadow를 사용한다. 메뉴 구조와 금융 동작은 그대로다.

390×844 브라우저에서 기록 관리 2×2, 버튼 높이 약 44px, 모달 1열, 문서 가로 overflow 없음 확인. reduced-motion에서 transition을 끈다. 이번 기록 모달의 기존 공통 CSS 우선순위 충돌을 보완했다.
