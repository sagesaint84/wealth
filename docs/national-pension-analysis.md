## 저장과 하위 호환

기존 insurance_accounts 상품 내부에 선택 필드 national_pension_analysis를 둔다.
별도 금융 파일을 만들지 않는다. 기존 yearly_contributions의 year/deposit,
total_paid_amount, 월 연금액, 예상 수령액, 날짜, owner는 변경하지 않는다.

```json
{
  "national_pension_analysis": {
    "revision": 1,
    "membership_periods": [],
    "annual_details": [],
    "tax_years": [],
    "scenario": {}
  }
}
```

분석 필드가 없는 상품은 revision=0의 빈 분석으로 읽으며 읽기 migration은 없다.
일반 상품 편집은 이 메타데이터를 서버 최신값으로 보존한다.
분석 삭제는 빈 상태와 증가한 revision을 남겨 ABA 충돌을 방지한다.
원래 상품 삭제는 내부 메타데이터도 함께 삭제하는 기존 계약이다.

GET/PUT/DELETE /api/insurance-accounts/{id}/national-pension-analysis는
현재 로그인 username의 국민연금 상품만 대상으로 한다. PUT/DELETE는 revision과
expected_history를 함께 비교한다. 새 가입유형·세금 정보와 연도별 실제 납부 이력은
서로 다른 저장 action이다. 어느 쪽이 바뀌어도 분석 저장의 이전 이력 검사로 충돌을 거부한다.
같은 portfolio.json canonical RMW 잠금 안에서 검증·수정·atomic write를 수행한다.
파생 스냅샷이나 금융 updated_at을 갱신하지 않고 분석 필드만 변경한다.
POST /national-pension-analysis/calculate는 revision·이력 snapshot을 확인하되 저장하지 않는다.
분석 요청 중에는 닫기·ESC·별도 납부 이력 저장을 막아 전송 중 요청을 취소했다고
오인하지 않게 한다. 요청 완료 후 초안 취소·닫기는 정상 동작한다.

## 가입유형과 부담액

membership_periods의 year/start_month/end_month는 실제 확인한 기간이다.
membership_type: workplace(사업장), regional(지역), voluntary(임의),
continued(임의계속), unknown(미확인).
workplace_role: employee(근로자), sole_proprietor(개인사업장 사용자),
corporate_representative(법인 대표), unknown. 사업장이 아닌 유형의 역할은 미확인이다.
같은 해 유형 변경은 가능하지만 기간 중복·역전은 거부한다. 미입력 기간은 미확인이다.
가입유형은 납부액을 자동 분할하거나 수정하지 않는다.

annual_details는 연도별 agency_paid(공단 실제 보험료), personal_paid(본인 부담),
employer_paid(사용자/사업장 부담), unpaid, future_expected, deductible_amount,
paid_months, payment_date, source, verified를 저장한다.
금액 null은 미확인이고 0은 명시적으로 확인한 0원이다. 미래 예상액·공제 참고액은
과거 실제 지출이나 미래 cashflow에 자동 투입하지 않는다.

근로자의 회사 부담분을 개인 비용/공제액에 넣지 않는다. 개인사업장 사용자가
전체 보험료를 부담했을 가능성도 공제액 확정 근거가 아니다. 법인 대표의 법인
비용과 개인 공제는 구분한다. 역할·급여·보험료 액수만으로 어느 값도 추정하지 않는다.

## 세금 정보와 공식 근거

tax_years에는 year, income_type, gross_salary, business_revenue, business_income,
expenses, taxable_before, allowed_deduction, actual_tax_saving, saving_date,
source, verified를 저장한다. 사업소득금액의 결손은 음수 참고값으로 허용하며
이를 과세표준으로 자동 대체하지 않는다. 나머지 금액은 0 이상 또는 null이다.
출처는 agency / tax_return / user / estimate / unknown이고 기본은 unknown이다.
개인 입력의 확인 표시는 사용자 확인 선언이며 공식 자료를 자동 검증한 것은 아니다.

국민연금은 연금보험료 **소득공제**이며 IRP/연금저축 **세액공제**와 별개다.
확인한 taxable_before와 실제 allowed_deduction을 사용하는 경우에만
공제 전후 누진 산출세액 차이를 계산한다. 여러 구간을 넘어가는 공제도 구간별로 계산한다.
공제액은 과세표준까지만 적용하고 제한 여부를 보여 준다.
Decimal로 계산하고 결과는 0.01원 단위 반올림한 이론적 비교값이다.

공식 출처: [국세청 종합소득세 귀속연도별 세율표](https://t.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7667&mi=2227),
확인일 2026-10-13. 페이지에 명시된 2017, 2018~2020, 2021~2022,
2023~2025년 구간을 등록했다. 2026년은 별도 확인한 다음 공식 자료로 등록했다.
2013~2016년 및 2027년 이후는 미지원이다. 최신 표를 소급하거나 미래 연도로 연장하지 않는다.

- [소득세법 제55조, 2026-07-01 시행 법령](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034035335)

2026년 귀속 기본세율은 과세표준 1,400만원/5,000만원/8,800만원/1억5,000만원/
3억원/5억원/10억원 경계에 따라 6/15/24/35/38/40/42/45%를 적용한다.
중간예납 안내의 기본세율만 사용하며 중간예납의 2배·절반 계산을 연간 소득공제
분석에 적용하지 않는다. 기존 연도별 세율과 구간별 누진 계산 방식은 유지한다.

근거 확인 보조: [국세청 2020년 귀속 근로자 연말정산 안내](https://b.nts.go.kr/comm/ntsFileDown.do?filePath=%2Fupload%2Fnts%2F02%2F0201%2F2020%EB%85%84_%EA%B7%80%EC%86%8D_%EA%B7%BC%EB%A1%9C%EC%9E%90%EC%9A%A9_%EC%97%B0%EB%A7%90%EC%A0%95%EC%82%B0_%EC%95%88%EB%82%B4%28%EA%B2%8C%EC%8B%9C%EC%9A%A9%29.pdf).
본인 납부액과 실제 인정 공제액은 별도 입력한다. 가입유형으로 공제 적격성을 판정하지 않는다.

allowed_deduction, 계산한 estimated_reduction, 신고 확인 actual_tax_saving은
각각 표시한다. 예상 감소분은 환급액이 아니다. 다른 공제·감면·최종 결정세액·
지방소득세는 계산하지 않으며 지방소득세를 단순히 10% 가산하지 않는다.
미확인·계산 추정 출처, 미확인 기준금액은 미산정이다.
2026년에도 추정 금액은 source=estimate로 기록하고 신고 확정값으로 취급하지 않는다.
source=tax_return 및 verified=true인 경우만 결과에 세금 신고 자료 확인값으로 표시한다.
다른 확인 입력값은 신고 확정 여부 미확인으로 구분한다. 입력 절세액도 동일한
신고 확인 조건을 충족한 경우에만 신고 확인 절세액으로 표시한다. 이 구분은 계산
응답의 표시 메타데이터이며 저장 구조나 IRR의 실제 절세액 포함 조건을 변경하지 않는다.
신고 확인 입력을 사용한 계산 결과도 예상 산출세액 감소분이며 확정 혜택·환급액이 아니다.

2026년 합성 테스트는 8개 구간의 세액, 각 경계 전후 1원, 여러 구간에 걸친 공제,
과세표준 한도, 0원 공제, 추정/신고 확인 입력 구분 및 2027년 미지원을 검증하도록 작성했다.

## 현금흐름과 시나리오

원래 공단 월 연금액과 누적납입액은 참고 표시만 한다. 시뮬레이션 입력은 별도로
저장하며 기존 값을 덮어쓰지 않는다. 생년월일은 종료 나이 날짜를 정하는 사용자 가정이다.
기준일, 예상 개시일, 미래 납부 시작/종료일, 월 본인 보험료와 연간 증가율 또는
사용자 지정 납부 일정, 물가율, 연금액 기준, 물가연동 여부와 종료 나이를 모두 표시한다.
수령 종료일은 75/80/85/90/95세 생일 직전까지이며 추가 나이도 선택할 수 있다.
종료 나이는 사망 예측이 아니며 국민연금은 평생 지급되는 구조다.

미래 보험료는 입력한 시작일 명목 월액 × (1+연간 증가율)^(경과 개월/12)로
월별 생성한다. 사용자 일정 선택 시 그 일정이 우선이며 빈 일정은 명시적인 0원 가정이다.
납부 종료일은 가입일·연금 개시일·maturity_date로 추정하지 않는다.
각 나이 시나리오는 종료일까지의 지출·수령만 포함한다. 월 납부일의 말일은
해당 월 마지막 날짜로 조정하며 원래 시작일의 일자를 계속 기준으로 한다.

현재가치 월 연금액은 기준일~개시일 간 입력 물가율로 개시 시 명목금액으로 환산한다.
미래 명목 입력은 개시 시 명목값 그대로다. 이후 수령액 물가연동은 별도 선택이다.
실질 출력은 과거·미래 모든 흐름을 동일 기준일과 동일 입력 물가율로 조정한다.
물가율은 역사 실측 물가지수가 아니라 사용자 고정 가정이다.

연간 자료의 개인 지출은 검증 표시·출처가 있는 personal_paid만 사용한다.
payment_date 또는 사용자가 선택한 6월 30일/12월 31일 근사를 사용하며 근사 적용을 표시한다.
연간 총액에 입력한 대표일도 실제 납부 월수가 1개월로 확인된 경우를 제외하면 날짜 근사로 표시한다.
기준일 이후가 되는 근사 날짜는 과거로 간주하지 않는다. 과거 기록 완전성도 명시적으로 확인해야 한다.
공단 총액을 개인 지출로 사용하는 옵션은 기본 OFF이고 선택 시 **가정 시뮬레이션**으로 표시한다.
미확인 개인 지출을 공단 총액이나 회사 부담분으로 조용히 대체하지 않는다.

미래 보험료·수령 합계·미래 순흐름과 과거 포함 순흐름은 구분한다.
과거 불완전 시 전체 순흐름·원금 회수·IRR은 미산정이다.
회수 시점은 같은 날짜의 흐름을 합산한 누적 흐름의 첫 회수 날짜이며 할인 회수가 아니다.

## IRR 수치 계약과 제한

날짜별 동일일 흐름을 합산한 XIRR이다. ACT/365.2425를 사용하고 지출은 음수,
수령은 양수다. log(1+r) 구간 [-30,30]에서 bisection을 최대 256회 수행한다.
구간 폭 ≤1e-10와 스케일 조정된 상대 NPV 잔차 ≤1e-10를 함께 만족해야 반환한다.
계수 절댓값도 log 영역에서 정규화하여 극단적인 금액 비율의 underflow를 피한다.
단일 cashflow 금액은 절댓값 1e100까지, 목록은 5000개까지 허용한다.
정확히 합계가 0인 혼합 흐름은 0% 해를 반환한다.

이 엔진은 날짜순 부호 변경이 한 번인 유일해 흐름만 자동 산정한다.
부호가 여러 번 바뀌면 **복수 해 가능성 미배제**로 미산정한다. 모든 해를 열거하거나
일부 해를 임의 선택하는 엔진은 이번 구현에 포함하지 않았다. 같은 날짜만 있거나
지출/수령 한쪽만 있는 경우, 범위 밖 해, 수렴 실패는 명시적 상태이며 임의 0%가 아니다.

기본은 세전 수령 IRR이다. 선택 시 신고에서 확인한 actual_tax_saving과 확인일만
별도 현금흐름으로 더한다. 계산한 예상 감소분이나 미래 절세액을 자동 넣지 않는다.
입력한 신고 확인 혜택에 한정된 시나리오이며 미입력 연도 혜택을 추정하지 않는다.
절세액 추가로 부호가 여러 번 바뀌면 그 시나리오는 미산정일 수 있다.
수령 세후 IRR은 세법/사용자 가정을 충분히 등록하지 않아 미지원이다.

## HOME 보험 부분 집계

소유자 필터 후 유효한 일시금/해약환급금 입력액과 양수 누적납입액을 가진
상품만 합계한다. 국민연금·IRP·월지급 연금과 근거 누락·불일치는 제외한다.
상품별 수익률 평균 대신 (대상 예상액 합계 - 대상 납입액 합계)/대상 납입액 합계를 사용한다.
대상 수/전체 수와 일부 상품 기준 여부를 화면에 표시한다. 대상이 없으면 —,
정확한 0%는 0.00%다. 이 지표는 IRR·연환산·확정 수익률이 아니며 원래
보험 평가액·비중·순자산·안전자산·금융 데이터는 그대로다.

## 사용자 수동 검증 순서

1. 실제 데이터 없이 합성 복사본에서 신규 서비스·API·Chrome 테스트와 기존 회귀를 실행한다.
2. 같은 해 근로자 1~4월/개인사업장 사용자 5~12월을 저장하고 중복 4~5월을 거부하는지 확인한다.
