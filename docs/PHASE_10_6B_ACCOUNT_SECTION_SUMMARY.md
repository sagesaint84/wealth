# Phase 10.6B — 증권/은행 계좌 섹션 상단 Summary

## 목적

AccountInfo PDF 가져오기 이후 계좌 수가 늘어나는 상황에서도 자산/계좌 관리 화면에서 전체 계좌 현황을 스크롤 전에 파악할 수 있도록 증권 및 은행 탭 상단에 요약 정보를 제공한다.

## 증권 탭

증권 계좌 목록 위에 다음 4개 요약 카드를 표시한다.

- 총 증권계좌 / 증권사 수
- 총 증권자산 (주식자산 + 기존 계좌 예수금 기준)
- 주식자산 평가금액
- 원화/달러 예수금

`모두` 조회일 때는 소유자별 증권계좌 수를 함께 표시한다.

AccountInfo PDF에 적힌 참고 잔액은 증권 예수금으로 사용하지 않는다. 증권 요약의 예수금은 기존 Wealth 증권계좌의 `cash_krw`, `cash_usd`만 사용한다.

## 은행 탭

은행 영역은 실제 예금계좌와 부채 계약을 구분한다.

- `총 은행계좌`: 자유입출금 + 예·적금 계좌 수. 대출/마이너스통장 약정은 별도 계좌로 중복 합산하지 않는다.
- `자유입출금`: 일반 은행계좌 수
- `예·적금`: 예금·적금·청약 계좌 수
- `대출·한도약정`: 일반대출/마이너스통장 약정 수
- `현재 부채`: 대출 약정의 `current_balance`와 legacy 음수 은행잔고를 합산한 실제 사용 부채

예를 들어 자유입출금 5개, 예·적금 1개, 마이너스통장 약정 3개가 모두 미사용이면 `총 은행계좌 6개`, `대출·한도약정 3개`, `현재 부채 ₩0`으로 표시한다.

`모두` 조회의 소유자별 계좌 수 역시 실제 은행계좌(자유입출금 + 예·적금)만 집계한다.

## 데이터 소스

- 증권: 기존 `/api/accounts?group=All&owner=모두`
- 은행: 기존 `/api/dashboard`의 `bank_accounts`, `savings_accounts`, `loan_accounts`

새 backend/API/persistence 스키마는 추가하지 않는다.

## UI 갱신

- 가족 구성원 필터 변경 시 재집계한다.
- 증권 계좌 목록과 은행 요약 카드의 기존 렌더 호스트만 관찰한다.
- body 전체 mutation observer를 추가하지 않아 이전 observer feedback-loop 유형의 회귀를 피한다.
